# P1.3 — Execution state machine (virtual clock)

**Goal:** The heart: a `TimerSession` that executes a flattened instance list, computing all state from **wall-clock anchors** — never tick accumulation. This is the part the whole app stands on; the test battery is the deliverable as much as the code.

**Prereqs:** P1.2 green.

**Read-first:** CONVENTIONS §2 (purity, anchors); `multitimer-spec/SPEC/engine.md` §2–§3 IN FULL (state machine + zero-crossing semantics to mirror); UI-REFERENCE items 1–3 (what states must be displayable).

## Tasks

1. **API:** `TimerSession(instances, clock)` with `start(atNow)`, `pause()`, `resume()`, `skipNext()` (">"), `jumpTo(ordinal)` (list-menu), `reset()`, and `snapshot(now) -> TimerSnapshot`.
2. **States (from snapshot):**
   - `notStarted` (shows total planned)
   - `running {ordinal, remaining, currentLabel, totalRemaining}`
   - `paused {same}` (user-paused mid-interval)
   - `awaitingAdvance {ordinal}` (manually-complete interval hit zero; timer holds AT ZERO until user advances — this is Planner's deliberate deviation from MultiTimer's pause-at-next-start)
   - `finished` → immediately equivalent to `notStarted` (fresh), per the last-interval rule below.
3. **Advance rules:** auto-finish instance ends → next starts (or timer finishes). Manually-complete instance ends → `awaitingAdvance`; user advance (skipNext) → next instance. Last instance: auto-finish → reset immediately; manually-complete → `awaitingAdvance`, then reset.
4. **Edge semantics (mirror SPEC §2, test each by name):**
   - Pause legal only from `running`. Resume only from `paused`. Zero-crossing while paused is impossible (paused time doesn't consume duration — remaining frozen).
   - If `pause()` arrives when the interval already reached zero: treat as `awaitingAdvance` (if manually-complete) or as no-op post-transition (auto-finish already moved).
   - Boundary recomputation always from anchors: `snapshot(t2) − snapshot(t1)` consistency under arbitrarily warped virtual time (no drift over long/suspended periods).
   - `skipNext()` legal from running/paused/awaitingAdvance; ends current instance (terminal state: `skipped` if it never zeroed... define: skipped when ended before zero, `done` when at zero — cut/moved unused in v1 flows but the enum exists).
   - `jumpTo(ordinal)`: current instance ends (terminal per above); if session was running, the target starts running; if paused/notStarted, session sits at target's start, **paused-ready** (remaining = full).
   - Negative/empty cases: skip on last instance = finish+reset; jump to same ordinal = restart that instance.
5. **Terminal states:** every instance end emits `{ordinal, defId, terminal}` through the injected `EventSink` (P1.4 consumes for logging; here just emit).

## Required tests (~40+; the battery)

Grouped: transitions legality matrix · anchors & drift (warp virtual clock: hour-jumps, suspend/resume, backwards clock → clamped/sane) · boundary races (pause at t-1ms, at t, at t+1ms) · auto/manual × first/middle/last · skip during each state · jump during each state · empty/1-interval timers · duplicate snapshots are pure (no state mutation from snapshot()).

## Definition of Done

`dart test` green; purity green; report includes a state-transition table as implemented. This part gets the deepest orchestrator review — expect rework requests.

**Out of scope:** sound/notification side effects, persistence of run state (never persisted), UI.
