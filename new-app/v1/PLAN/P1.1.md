# P1.1 — Engine data model + persistence

**Goal:** All engine entities, their drift-backed persistence, and the append-only change log — with the v1 groundwork fields (completion state, trigger method) present but inert. Boards are entities (no singleton hacks).

**Prereqs:** P0.1 green. (P0.2 parallelizable.)

**Read-first:** CONVENTIONS §1–2; `new-app/v1/OUTLINE.md` D2–D4; `multitimer-spec/SPEC/data-model.md` (reference only — do not copy schemas).

## Tasks

1. **Entities** (pure Dart domain types, drift tables mirror them):
   - `Board {id, name}`; `IntervalTimer {id, boardId, name, color}` (one per board in v1, but modeled 1:N).
   - `IntervalDef {id, timerId, name?, color, durationSeconds (>0), autoFinish, endAlertSoundFile?, sortIndex}` — plus groundwork fields `completionDefault` (always `notCompleted` in v1) and `trigger` (always `order`).
   - **Interval tree:** intervals nest in groups. Model as an ordered tree: either separate `GroupDef {id, timerId, repeatCount (≥1), orderIndex, parentGroupId?}` rows + `IntervalDef.parentGroupId?`, or a structure JSON column on the timer — executor picks, but these ops must be cheap and tested: group(selection), ungroup(outermost), duplicate(selection), delete(selection), reorder/move.
2. **Persistence:** drift; DB file under XDG data dir (interface-injected path; `dart:io` stays OUT of the engine — the engine defines `Store` interfaces, the *drift implementation lives in the engine package but takes an injected path and is only constructed by the app*; if drift forces `dart:io`, put drift behind a `Store` interface in a `planner_engine/storage/` with the purity test allowing `dart:io` only in files under `storage/impl/` — document the exception).
   - Migrations framework from day one (`schemaVersion`).
3. **Change log:** append-only `EventLog {id, timestampMs, kind, payloadJson}`. Every mutation (edits, tree ops) appends an event. Terminal-state entries (`done|cut|skipped|moved`, with instance identity) also land here (written from P1.4).
4. **Clock + event-sink interfaces** defined here (`Clock.now()`, `EventSink.emit(...)`), used by everything later.

## Required tests

- Round-trip: build a timer w/ nested groups → persist → load → identical tree.
- Tree ops: each op's structural effect incl. nested cases, single-interval group, duplicate-below-last-selected with non-sequential multi-selection (see UI-REFERENCE + FINAL outline rules), ungroup-outermost-only.
- Change log: ops produce ordered, complete events.
- Purity test still green.

## Definition of Done

`dart test` green in engine (expect ~25+ tests), report appended. No UI changes.

**Out of scope:** flattening, execution, any Flutter code.

## Report — P1.1 — 2026-10-28
Status: done
Tests: engine `dart test` 32/32 green (21 tree-op, 6 storage/round-trip/change-log, 2 purity, 3 Clock contract); app `flutter test` 5/5 (untouched); `dart analyze` clean in both packages; `scripts/test.sh` green end-to-end
Decisions made:
- **Tree modeling: `GroupDef` rows + `parentGroupId` columns** (relational option). Domain keeps an immutable `IntervalTree` (`DefNode`/`GroupNode`); `parentGroupId`/`sortIndex`/`orderIndex` columns are the storage encoding. `saveTree` = whole-timer rewrite (delete+reinsert) in one transaction — trivially correct at v1 scale; per-row diffs can come later if profiling ever demands it.
- **Selection semantics defined in `tree.dart` docs + tests** (nothing upstream pinned them): group = siblings only, non-adjacent allowed, lands at first selected position, in-between items stay outside; single-interval groups allowed; duplicate = deep copy (fresh UUIDs) in relative order below the LAST selected; ungroup = dissolves exactly the targeted group; delete = cascades emptied groups; move = cycle-guarded, index-after-removal clamped.
- **`dart:io` exception documented**: confined to `lib/storage/impl/db_opener.dart`; purity test enforces `dart:io` nowhere else, flutter nowhere. Tests use `NativeDatabase.memory()` (no io).
- **Change log ordering**: explicit monotonic `seq` column (rowid ordering is an SQLite detail); `EventLogEntry` carries `seq`.
- **Dropped the `uuid` package**: it conflicted with the app side (system_tray pins uuid ^3 vs engine ^4 — pub resolution failed). Engine now ships a 15-line `newUuidV4()` (Random.secure, version/variant bits set); `DriftStore` takes an injectable `GenerateUuid`.
- **drift toolchain quirks (upstream-worthy)**: drift_dev 2.35.2 / Dart 3.13.7 — `int32()` and `textEnum<>()` column types silently produce an EMPTY `.g.dart` with zero errors. Using `integer()` (same SQLite type) and name-based enum mapping in DriftStore. Documented in `new-app/README.md`. A fresh empty-part repro + upstream report is optional follow-up.
- Deps: + drift, sqlite3 (transitive of drift/native), dev: drift_dev, build_runner. − uuid (see above).
Deviations from part file: none functionally. Note: `Clock`/`EventSink` defined (P0.1 defined Clock; EventSink added here); DB file path stays app-injected as specified — no XDG logic in engine (P2.1 wires it).
Suggested tweaks to later parts: P1.4 writes terminal-state events with kinds like `run.terminal` (EventLog kinds are free-form strings by design). P2.1: construct `DriftStore(PlannerDb(openSqliteFile(<xdg path>)), clock)`. Watch drift_dev releases for the int32/textEnum codegen bug; if fixed, porting back is trivial but unnecessary.
