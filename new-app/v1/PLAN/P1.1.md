# P1.1 — Engine data model + persistence

**Goal:** All engine entities, their drift-backed persistence, and the append-only change log — with the v1 groundwork fields (completion state, trigger method) present but inert. Boards are entities (no singleton hacks).

**Prereqs:** P0.1 green. (P0.2 parallelizable.)

**Read-first:** CONVENTIONS §1–2; `new-app/v1/OUTLINE.md` D2–D4; `multitimer-spec/SPEC/data-model.md` (reference only — do not copy schemas).

## Tasks

1. **Entities** (pure Dart domain types, drift tables mirror them):
   - `Board {id, name}`; `IntervalTimer {id, boardId, name, color}` (one per board in v1, but modeled 1:N).
   - `IntervalDef {id, timerId, name?, color, durationSeconds (>0), autoFinish, endAlertSoundFile?, sortIndex}` — plus groundwork fields `completionDefault` (always `notCompleted` in v1) and `trigger` (always `order`).
   - **Interval tree:** intervals nest in groups. Model as an ordered tree: either separate `GroupDef {id, timerId, repeatCount (≥1), orderIndex, parentGroupId?}` rows + `IntervalDef.parentGroupId?`, or a structure JSON column on the timer — executor picks, but these ops must be cheap and tested: group(selection), ungroup(outermost), duplicate(selection), delete(selection), reorder/move.
2. **Persistence:** drift; DB file under XDG data dir (interface-injected path; `dart:io` stays OUT of the engine — the engine defines `Store` interfaces, the *drift implementation lives in the engine package but takes an injected path and is only constructed by the app*; if drift forces `dart:io`, put drift behind a `Store` interface in a `planner_engine/storage/` with the purity test allowing `dart:io` only in files under `storage/impl/` — document the exception).
   - Migrations framework from day one (`schemaVersion`).
3. **Change log:** append-only `EventLog {id, timestampMs, kind, payloadJson}`. Every mutation (edits, tree ops) appends an event. Terminal-state entries (`done|cut|skipped|moved`, with instance identity) also land here (written from P1.4).
4. **Clock + event-sink interfaces** defined here (`Clock.now()`, `EventSink.emit(...)`), used by everything later.

## Required tests

- Round-trip: build a timer w/ nested groups → persist → load → identical tree.
- Tree ops: each op's structural effect incl. nested cases, single-interval group, duplicate-below-last-selected with non-sequential multi-selection (see UI-REFERENCE + FINAL outline rules), ungroup-outermost-only.
- Change log: ops produce ordered, complete events.
- Purity test still green.

## Definition of Done

`dart test` green in engine (expect ~25+ tests), report appended. No UI changes.

**Out of scope:** flattening, execution, any Flutter code.
