# P0.1 — Toolchain + monorepo scaffold

**Goal:** A building, testable, committed monorepo: Flutter SDK installed, `packages/planner_engine` (pure Dart) + `apps/planner` (Flutter Linux placeholder), test harness green.

**Prereqs:** none (first part).

**Read-first:** CONVENTIONS §2 (layer rules), OVERVIEW §Environment notes.

## Tasks

1. **Install toolchain** (needs sudo — if password-blocked, write BLOCKERS.md and ask the user to run):
   - `sudo pacman -S --needed flutter clang gtk3` (Arch; confirm `flutter doctor -v` afterwards; install anything else it demands for Linux desktop: ninja, cmake, pkg-config already present).
2. **Monorepo layout** under `new-app/`:
   - `packages/planner_engine/` — `dart create -t package`, name `planner_engine`. Pure Dart; add `test/` with one meaningful placeholder test (e.g. a trivial `Clock` interface contract test) so `dart test` is real.
   - `apps/planner/` — `flutter create --platforms=linux --project-name planner`. Title "Planner".
   - Root convenience: a `melos`-free approach — top-level `new-app/pubspec.yaml` using Dart workspace resolution (or a simple `Makefile`/script `new-app/scripts/*.sh` wrapping `dart test` / `flutter test` / `flutter build linux` across packages). Executor's choice; keep it boring and documented in `new-app/README.md` (create it: how to build/run/test).
   - App depends on engine via path dependency.
3. **Purity test scaffold** (CONVENTIONS §2): a test in engine asserting no `dart:io` / `flutter` imports exist. It will trivially pass now; it is load-bearing later.
4. **.gitignore** at repo root: add Flutter/Dart build artifacts (`**/build/`, `.dart_tool/`, `**/.flutter-plugins*`, etc.), `apps/planner/assets/fonts/` (fonts are local-only, P0.2 copies them there), `apps/planner/assets/sounds/` if created.

## Definition of Done

- `flutter doctor` reports no Linux-toolchain issues.
- From `new-app/`: `dart test` (engine) green; `flutter test` (app) green; `flutter build linux --release` succeeds.
- Repo committed on `main` (this part may work directly on main; parts from P0.2 on use branches).
- `new-app/README.md` documents build/run/test commands.

**Out of scope:** any UI beyond the Flutter counter placeholder, any engine logic, transparency (P0.2).
