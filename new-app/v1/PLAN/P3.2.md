# P3.2 — Board controls: interval-list jump, reset, skip — USER CHECKPOINT 2

**Goal:** The three control buttons under the dial + end-of-timer behavior. Completes the non-editor app: after this part the user can run a real timer session start-to-finish.

**Prereqs:** P3.1 green.

**Read-first:** UI-REFERENCE items 1–4 (control row + interval-list overlay); P1.3 §4 (skip/jump semantics).

## Tasks

1. **Control row** (3 buttons, icon buttons on cards):
   - **Interval list** (menu icon): opens modal overlay listing all instances in play order: `N. label` left, duration right (mirror UI-REFERENCE item 4: rows, separators, alternating subtle tint; current instance highlighted). Select → `jumpTo(ordinal)`, close.
   - **Reset (✕)**: confirmation dialog ("Reset timer?") → `reset()`.
   - **Skip (>)**: `skipNext()`.
2. **End-of-timer:** auto-finish last instance → immediate reset (notStarted); manually-complete last → `awaitingAdvance` then reset on advance. (Engine already does this; UI must render it correctly — no zombie states.)
3. **awaitingAdvance affordance:** dial shows `00:00` + a clear "tap to continue" affordance (e.g. pulsing caption replacing the ≫ next caption). Exact styling executor's call; must be unambiguous.

## Required tests (widget)

- List overlay: contents in order, current highlighted, jump dispatched, closes.
- Reset: dialog required (cancel does nothing), confirm resets.
- Skip button dispatches per state (disabled in notStarted? — decide: enabled only when a session exists: running/paused/awaitingAdvance; document).
- End-of-timer flows render final state correctly.

## Definition of Done — user checkpoint

`flutter test` green; **user runs a real session on desktop**: start, pause/resume, open list & jump, skip, manual-complete hold at zero, tap-through, finish → reset. Sign-off recorded in report.

**Out of scope:** editors, alerts (still firing only via debug path).
