# P0.2 — Desktop shell prototype (risk-burner) — USER CHECKPOINT 1

**Goal:** Prove the three riskiest desktop unknowns in a throwaway-but-kept shell: (a) fully transparent window content under standard KDE decorations with compositor blur, (b) ProLisa/MonoLisa fonts rendering, (c) close-to-tray. Ship a static mock board screen — no engine, no logic.

**Prereqs:** P0.1 green.

**Read-first:** `new-app/v1/OUTLINE.md` D6–D11; UI-REFERENCE items 1–3 (board screen appearance to mock); ALSO view the images themselves: ../../../multitimer-spec/REFERENCE-IMAGES/IMG_6214.PNG, "../../../multitimer-spec/REFERENCE-IMAGES/Screenshot 2026-10-27 at 8.09.21 PM.png"; CONVENTIONS §2.

## Tasks

1. **Fonts:** copy `ProLisa_Regular.ttf` (+ Bold if present) and `MonoLisa-Medium.ttf` (+ MonoLisa-Black for emphasis) from `/usr/local/share/fonts/p/` into `apps/planner/assets/fonts/` (**gitignored**). Register in pubspec. `FontFamily` constants in a theme file. Digits everywhere use MonoLisa.
2. **Transparent window:** GTK recipe in `apps/planner/linux/runner/my_application.cc` — `gtk_widget_set_app_paintable(TRUE)`, RGBA visual when composited (known-good recipe; flutter/flutter#152154 documents the 3.22+ regression and fix). Keep **standard window decoration** (do NOT undecorate). Scaffold background: fully transparent (`Color(0x00000000)` at app level; `#080808` is NOT used as window background).
3. **Theme tokens** (`apps/planner/lib/theme.dart`):
   - text/foreground `#f2f2f2`; accents `#ff00b1 #4800ff #0055ff #00a8ff #00ad6b #b8ff00`;
   - "card" style: semi-transparent dark (e.g. `Colors.black.withOpacity(0.45)` — executor may tune for legibility over blur) rounded rectangle, used for panels/chips/cards.
4. **Static mock board:** one screen mimicking UI-REFERENCE item 1 (dial circle with ring + tick marks, `03H 00M`-style MonoLisa readout, a caption row, a 3-button control row, an interval chip card list with a group bracket) — hardcoded values, no behavior except hover. Close enough to judge the aesthetic.
5. **Tray:** on window close → hide to system tray (package: `tray_manager` or `system_tray`, executor picks; tray icon: any generated placeholder PNG, gitignored asset dir). Tray click → show window. Provide "Quit" tray menu item that actually exits.

## Required tests

- Widget test: mock board renders the expected texts/cards/bracket structure.
- Manual DoD covers the visual/tray parts (no honest way to automate on a composited display).

## Definition of Done — **user verifies on their KDE desktop**

- Window: standard KDE titlebar; content background fully transparent with blur behind; cards readable; dark theme; ProLisa text + MonoLisa digits visibly correct.
- Close button hides to tray; tray click restores; Quit exits.
- `flutter run -d linux` instructions in README; part committed on branch `part/P0.2`, merged after user sign-off.

**Out of scope:** real timer behavior, engine wiring, notifications, sounds, editors.

## Report — P0.2 — 2026-10-28
Status: done (user checkpoint 1 passed 2026-10-28)
Tests: app `flutter test` 5/5 green (board structure/text; no goldens); `dart analyze` clean; `flutter build linux --release` green; visual/tray DoD verified by user on KDE desktop
Decisions made:
- **Tray package: system_tray 2.0.3** (part offered tray_manager or system_tray). tray_manager 0.8.0 (nativeapi-based) silently failed SNI registration on this desktop: Dart-side create/setIcon/setVisible all "succeed", no errors printed, but the item never reaches org.kde.StatusNotifierWatcher and no `org.kde.StatusNotifierItem-*` bus name is ever claimed. Diagnosed against libnativeapi-core source (dispatcher/tray_icon_linux.cpp); failure is inside nativeapi — avoided rather than patched. system_tray uses its own per-platform plugin + ayatana-appindicator and registers immediately.
- **Window decoration: server-side (SSD) everywhere** (D11). Flutter template draws a GTK header bar (CSD) on Wayland, ignoring the user's KDE theme — flagged at checkpoint 1. Fix: never set a titlebar widget, so GTK 3.24 requests SSD via xdg-decoration and KWin renders the user's theme. Confirmed by user.
- Control row mocked with **6 buttons** per reference image (part text said "3-button"; image is ground truth).
- Close-to-tray: window_manager `setPreventClose` + hide; restore via tray menu "Show Planner" (Linux panels open the menu on icon clicks and deliver no click events to apps — KDE-idiomatic); tray "Quit" = real exit.
- Fonts: MonoLisa lives in `/usr/local/share/fonts/m/` (part said `/p/`); ProLisa in `/p/` as documented.
- Tray icon PNG is a gitignored local-only asset; committed `scripts/gen_tray_icon.py` regenerates it.
- Toolchain: added `libayatana-appindicator3-dev` (system_tray Linux build dep).
Deviations from part file: tray package choice within the part's two options (documented above); decoration approach revised after checkpoint feedback; fonts source dir corrected. Mock is intentionally throwaway (all values hardcoded; real board = P3.x).
Suggested tweaks to later parts: P5.1 (alerts/notifications): avoid nativeapi-based packages on Linux until libnativeapi fixes the silent SNI failure (watch tray_manager >0.8 issues); the appindicator/SNI click limitation also applies to notification actions. Remember fresh-clone needs fonts + `python3 scripts/gen_tray_icon.py` before `flutter run` (README covers it).
