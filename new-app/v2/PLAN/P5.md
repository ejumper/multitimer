## P5.1 — New Events (quick capture)

**Goal:** the outline's capture flow, with both finish buttons and top-insertion.

1. The bottom-bar **New Event** button opens the interval editor in **event mode**: dated (Time) toggled ON; between the title and the option toggles sit **Date** boxes (`dd mm yy`) and the first option toggle **"Overwrite Default Timer"** (default from P5.2, off).
2. **Save** = insert as the **first interval** of the target day's plan (top-insertion — projection-aware placement is explicitly v3). **Save & edit timer** = same insert, then open that day's board + timer editor focused on the new interval (the user's two-button design).
3. **Overwrite ON** = the day's plan becomes a new single-interval timer (replacing the default). **Overwrite OFF with no default set** = the day's plan becomes the single event anyway (`TODO(micro)`: the outline's only sane fallback — confirm at review).
4. **Overlap blocking** (v2-outline overrides the North Star): if the event's occupancy window `[trigger, trigger+duration)` overlaps an existing dated interval on that day, **error and refuse to save** until the time is changed. Open dated events occupy a point (`TODO(micro)`: conflict only at the exact trigger — confirm).
5. **Past-due events** save fine and are **flagged late** (they fire at the day's next run start per P1.4). Adding an event to a future day is a write → that day materializes (P4.1, by design).
6. The event's other fields (name, color, alert, duration toggle, auto-finish) are the editor's normal ones.

**Pinned tests:** event-mode field layout + defaults · both buttons' flows (insert position + focus) · overwrite toggle both ways + no-default fallback · overlap matrix (contained/edge-touching/open) blocked-or-saved · past-due flagging · future-day materialization on capture.
