**Goal:** everything an interval can *be* in v2: optional duration (**Open**), trigger time (**Dated**/**walls**), and **completion state** — with the engine semantics fully pinned and the editor exposing the new fields. The dial still exists in this phase and is the eyeball surface for walls and holds.

**Phase verification:** engine matrices green (`bash scripts/test.sh`), editor toggles eyeballed from the bundle, a dated interval visibly interrupting & resuming a running timer on the dial. Then user checkpoint.

## P1.2 — Open semantics (no duration)

**Goal:** Open intervals behave exactly like a zero-duration manual interval — the user's "go to the store after studying" case.

1. An Open instance, when reached with the chain running: **instant → its end alert → `awaitingAdvance` (hold)** — identical to duration-0 today. `done` logged at the instant it's reached (it consumed its whole length of zero).
2. **Auto-finish requires a duration**: engine ignores/rejects `autoFinish` on a duration-less def (defense in depth under the editor's graying).
3. Pre-completed Open instance reached → flies past (no hold) — covered by P1.3's tests, note the interaction here.
4. Projection/totals with Open items: planned total = sum of known durations + an "open" marker (never pretend a finite total).

**Pinned tests:** open-hold matrix (start/reached-mid-run/reached-last/pre-completed) · auto-finish-on-open is inert · totals expose open-ness.

## P1.3 — Completion semantics (engine)

**Goal:** the completion model — marks orthogonal to execution (CONVENTIONS §3 rules 1–3).

1. **Mark API**: `toggleMark(ordinal)`, `resolveHold(completed: bool)` (the Enter/"not completed" pair), reachable for *any* ordinal at *any* time; marks do not move the cursor except via rule 2's first clause.
2. **Checkbox-current = finish + complete**: ends the current instance (`done` — "user moved past it"), marks completed, advances per normal transition rules (works mid-duration and at a hold).
3. **Fly past**: a pre-completed instance reached by the run emits `InstanceEnded(skipped)` and the chain continues instantly (no hold even if manual, no duration consumed). Pre-completed last instance ends the run.
4. **Auto-complete**: an auto-finish instance running its course marks completed. `cut`/`skipped` marks not-completed by default (overridable afterward — marks are toggleable anytime).
5. **Hold resolution**: `resolveHold(true)` = completed + advance (the Enter path); `resolveHold(false)` = not-completed + advance. A hold never auto-resolves by time.
6. **Reset clears**: marks, adjustments, suspend slot (P1.4), cursor → `notStarted`. (The user's explicit rule.)
7. **Logging**: `InstanceEnded` gains the mark; run-log entries record terminal + completion.

**Pinned tests:** the named matrix — mark-current-mid-run · mark-current-at-hold · mark-future-then-reach (each finish method) · mark-past-anytime · auto-complete · cut/skip defaults · hold resolution pair · reset-clears-marks · marks survive pause/resume/jump · exactly-once `InstanceEnded` under every path (v1 invariant).

## P1.4 — Walls (dated intervals) — interrupt & resume

**Goal:** the wall semantics of CONVENTIONS §3 rule 4, fully pinned. The riskiest engine work — the matrix is written before the code.

1. **Firing**: on settle, any wall whose `triggerTimeSeconds` (on its day) has passed while the run is live becomes current:
   - mid-flight item (running/paused with remaining) → **suspended** into the single suspend slot (position + remaining + state) — not logged, not `cut`;
   - held item (`awaitingAdvance`) → auto-resolves **completed** (its `done` stands) and the chain leaves it;
   - running **wall** → `cut` (actual < planned, mark not-completed) — later cuts earlier;
   - the wall runs with full remaining (or, dated + no duration → **alarm + hold** at its trigger).
2. **Return**: when the wall completes (auto-finish course / hold resolution / skip), the suspended item resumes with its saved remaining **in the state it was in** (running → running, paused → paused); slot empty → the run proceeds per normal rules (run already ended → back to `notStarted`; never-started case → the plan then runs from the top).
3. **Past-due at start**: starting a run with past-due wall(s) fires them first, in wall-time order, **flagged late** (snapshot flag for the UI badge), then the plan runs. Never-started days do not fire walls on their own (the North Star's "fires even if never started" is scoped to *run start* — walls never act on an idle timer).
4. **Pending-wall wait**: run reaches its end with a wall pending → `awaitingAdvance`-like paused state showing the countdown to the wall; the wall fires at its trigger; after it, the run is finished.
5. **Multi-wall**: each wall fires at its time; a wall firing while a wall runs cuts it; the suspend slot survives wall-vs-wall (the original plan item still resumes at the end).
6. Dated + repeat-group exclusivity is enforced at authoring (P1.5); the engine should also flatten defensively (dated inside repeats = treated as its wall firing once — `TODO(micro)`, prefer asserting instead if cheap).

**Pinned tests:** the named matrix — interrupt-mid-duration · interrupt-paused · interrupt-held · wall-cuts-wall · return-restores-state-and-remaining · past-due-at-start (single, multiple, flagged) · pending-wall countdown + fire-after-end · dated-no-duration alarm+hold · suspend-preserved-across-wall-vs-wall · sleep/jump past trigger fires-late on next settle · exactly-once `InstanceEnded` maintained.

## P1.5 — Editor: Duration & Time toggles

**Goal:** the editor exposes the new authoring fields (v2-outline "Dated Intervals and Intervals with no duration").

1. Below **Auto-finish**: two new toggles — **Duration** and **Time** (in that order). Duration ON = the existing duration editor (active-box model) shown beneath it; OFF = hidden, interval is Open. Time ON = a **time setter** in the same interaction model, 24h `HH|MM` at the bottom (`TODO(micro)`: seconds omitted for wall times — confirm at review).
2. **Auto-finish grays** (and forces off) when Duration is OFF.
3. **Exclusivity validation**: a dated interval can't be added to a group with `repeatCount > 1`; a group containing a dated interval can't have its repeat count set > 1. Blocked at the interaction with a brief reason (test both directions).
4. Interval rows show the shape (e.g. the time or an "open" marker) — row layout per the editor's existing vocabulary (`TODO(micro)`: exact row bits).
5. Defaults for the toggles come later from settings (P5.2) — hardcode ON/ON/OFF defaults for now with the seam noted.

**Pinned tests:** widget tests for the toggles (visibility, graying, force-off) · both exclusivity directions · engine round-trip of what the editor writes.
