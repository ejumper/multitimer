# P2 — The list view (the dial dies)

**Goal:** the timer's *only* display becomes the interval list — the timer-editor's row vocabulary (extracted, not duplicated) — and the completion semantics from P1 become the interaction. This is v2's biggest visible change.

**Phase verification:** **user checkpoint** — daily-drive one timer from the bundle: the look, checking items (current finishes, future flies past), Enter/"not completed" at holds, right-click jumps. The dial is gone.

---

## P2.1 — List core (replacing the dial)

**Goal:** the board's main area renders the flattened run as editor-style rows.

1. **Extract the editor's interval-row rendering** into a shared widget (CONVENTIONS §7) and rebuild the board's main area on it. The dial widget is removed from the board.
2. **Per row** (the v3 list spec, physics excluded): circular slot = **completion checkbox**; title top-left; duration slot top-right showing the live **`<time left>/<total>`** countdown (e.g. `10m5s/15m`) (`TODO(micro)`: v3-ideas says the duration sits top-LEFT, v2-outline + the editor say top-RIGHT — default: editor-faithful top-right; confirm at review); alert label bottom-left; background **fills left→right** as the instance elapses.
3. **Groups**: group rows as in the editor; repeat passes fill the group's background top→bottom per occurrence with the repeat count counting down (repeats left).
4. **Completion rendering**: completed rows **semi-transparent** (like passed dial ticks).
5. **Holds** (`awaitingAdvance`): the time slot shows **"wait"** and the row border **pulses** (the "» tap to continue" vocabulary).
6. Open intervals: no countdown — the slot shows the open marker / "wait" per state (P1's display contract).

**Pinned tests:** widget tests per state rendering (running fill, `<left>/<total>` text, group repeat counts, completed transparency flag, wait+pulse at holds) — structure/text only.

## P2.2 — Completion interaction

**Goal:** the agreed sentences are the interaction (CONVENTIONS §3 rules 1–2).

1. **Checkbox click**: current → finish + complete + advance (mid-duration included); future → mark only; past → mark only. All marks toggle freely (un-check = click again).
2. **Hold resolution**: **Enter = completed + advance** (happy path stays one-handed); the **"not completed"** button appears in the control row at holds (`TODO(micro)`: exact slot layout — the row keeps its 4-slot contract with silence in the far-right slot at holds; pin the contract in the board test like v1's slot test).
3. Auto-finish rows complete themselves (P1) — reflect the mark without user action.
4. **Reset clears marks** visibly (the checked rows un-check) — pin by test.
5. **Retry missed** (the user's redo-missed design): at run end, a **"Retry missed (n)"** action starts a derived run over only the not-completed items (a real new run over the same defs — the run log stays honest). Button placement: end-of-run affordance (`TODO(micro)`).
6. **Mark changes append `run.mark` change-log entries** (the app side, via `store.appendEvent`) so the history reflects post-end resolutions — the `run.terminal` payload's `completed` is the at-emission snapshot.

**Pinned tests:** checkbox current/future/past · Enter path · not-completed path · auto-complete reflection · reset-clears-marks at the widget level.

## P2.3 — Jump & scroll

**Goal:** navigation moves to the list itself.

1. **Right-click a row = jump** (the user's phrasing: "right clicking and confirming" — right-click opens a tiny confirm affordance → jump; `TODO(micro)`: confirm-step vs direct jump — default: direct jump with the v1 jump semantics: running stays running at the target, paused sits paused-ready). The **choose modal + its button are removed**.
2. v1 jump semantics carry over unchanged (jump emits `skipped` for the passed instance; jump-to-same = restart it).
3. **Center-snap + autoscroll**: the current row sits as close to center as the viewport allows (first row → top, last → bottom, short lists → no scrolling); auto-scroll to that position when the current instance changes; manual scrolling snaps back toward the current row's best position. **No scroll physics** (deadzone/slowdown = v3).
4. Keyboard: the existing board keys keep working against the list; add row-walk arrows + Enter-to-jump if cheap (`TODO(micro)`, keymap update rides along).

**Pinned tests:** right-click jump lands correctly (both start states) · choose-modal absence · autoscroll positions (overflow and no-overflow lists) · keyboard walk/jump if implemented.
