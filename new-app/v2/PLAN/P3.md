# P3 — The Library

**Goal:** plans get a home that isn't a day: the folder-organized **Library** (absorbing tasks and templates), **checklist mode**, **default rules**, and **save to folder**. The navigation shell (bottom bar) arrives here and grows with the later phases.

**Phase verification:** **user checkpoint** — task lists behaving like Apple Reminders (check, 3s sink, hide/show), folders organizing plans, "Gym is the Monday routine" set through the rules UI.

## P3.2 — Library page

**Goal:** the plan store.

1. **Folders**: create, rename (right-click = inline rename per the outline's long-press mapping), delete (confirm), drag-reorder plans within/between folders. Root = the library itself (v1's existing boards/timers migrate in as folder-less plans — `TODO(micro)`: whether v1's "My Board" becomes a folder or a plan; default: its timer becomes a plan at the root).
2. **Plan rows** (the outline's merged task/template row): title top-left; top-right = item count for all-open plans, total duration otherwise (`TODO(micro)`); created/modified date bottom-left. Drag-reorder as in the editor.
3. Opening a plan = its board (the outline's "temp board"): the standard list view + run controls, unbound to any day.
4. **Save to folder** (from any board's Library quick action — wired in P5.3; the operation itself lands here): folder picker → the plan is copied into the folder **with completion marks cleared** (P1.1's copy rule).

**Pinned tests:** folder CRUD + rename + reorder · row meta derivation · open-plan board · save-to-folder copies and clears marks.

## P3.3 — Checklist mode

**Goal:** all-open timers act like task lists — while staying timers (run controls everywhere).

1. **Derived default**: a plan whose intervals are all Open → checklist behavior; anything else → chain behavior. A per-plan override toggle (`TODO(micro)`: stored on the plan; default: derived).
2. **Checklist behavior**: checked items wait **3 seconds** (the un-check window — click again to undo) then sink below a **completed** section; a **show/hide completed** toggle lives in the plan board's bar (the outline's task-list bar button).
3. **Chain behavior**: items never move (sinking would wreck the chain display).
4. **Run controls stay on all timers** (the user's explicit call): play/reset/adjust on all-open timers too — playing an all-open timer walks the holds in order (P1.2 semantics).
5. **Reset = rewind + clear marks** on task lists too ("uncheck the camping list for next trip") — already the engine rule; pin the UI.

**Pinned tests:** derived mode matrix · 3s window then sink (fake-async) · un-check within the window stays put · show/hide toggle · run controls present and functional on all-open plans · reset un-checks everything.

## P3.4 — Default rules + rule resolution

**Goal:** plans can claim days (the outline's template rules).

1. Rule kinds on a library plan: **global default** / **day-of-week** / **day-of-month** / **specific date**, each with the outline's **repeat toggle** (weekday: "same day every week" off = that one date; monthday: "same day every month" off = that one date).
2. **Precedence**: specific date > monthday > weekday > global default (the outline: monthday overrides weekday). One plan may hold several rules.
3. Flows (on the plan board's bar — merged from the outline's temp-board bar): **make default** (confirmation popup) · **default for a day of the week** (calendar picker + repeat toggle) · **default for a day of the month** (same) — consolidated behind a "defaults" affordance (`TODO(micro)`: one menu button vs three; default: one menu button).
4. **Rule resolution API** (consumed by P4's placeholders): `resolvePlanFor(date) -> Plan?` honoring precedence. Storage: a `DefaultRules` table (kind/value/repeat) — enum mapping manual per BLOCKERS #2.

**Pinned tests:** precedence matrix (all four kinds, conflicts both ways, repeat off = one-off date) · resolution API unit tests · the three flows end-to-end (widget).
